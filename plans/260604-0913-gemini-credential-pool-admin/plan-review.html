Gemini Credential Pool and Admin Dashboard MVP

Add an n-project/n-service-account Gemini credential pool with weighted round-robin and failover, then expose a narrow internal admin dashboard for importing and managing credential JSON files, model allowlists, and pool health.

n project / n json Gemini OpenAI-compatible Admin opt-in Docker file-store Linux VPS Cloud Run out of MVP

Decisions

Backend First

Implement config, runtime pool, health, and failover before building dashboard controls.

Pool Runtime

Use GenAiRuntime with immutable active snapshots and explicit reload() for admin mutations.

Model Source

Use Phase 1 modelCatalog as the only model-admin source of truth.

Docker Store

Use file-store with a mounted persistent Docker/VPS volume. Cloud Run mutable import is out of MVP.

Dashboard Import

Borrow CLIProxyAPI-style JSON import, credential cards, health counters, model list, enable/disable, test, edit, and delete flows.

Secret Redaction

Never return or log raw service-account JSON, private_key, or private_key_id.

Admin Auth

All /admin/api/* requests use Authorization: Bearer <GATEWAY_ADMIN_TOKEN>. No query string, cookie, or public gateway key fallback.

No Full Clone

Borrow CLIProxyAPI credential/model UX only. Defer Anthropic, Claude Code, generic API console, proxies, and RBAC.

Red Team Remediation

Finding Severity Plan Fix
Admin import/patch/delete wrote store state without applying it to the live pool. Blocker Phase 2 now defines GenAiRuntime.reload() and atomic snapshot swap. Phase 4 mutations must reload or rollback.
Model admin endpoints had no schema/source-of-truth. Blocker Phase 1 now defines modelCatalog. Phase 4/5 can only edit that contract.
Container-local file-store safety was only documented, not enforced. High Plan now targets Docker/VPS mounted volumes and requires a hard startup guard for K_SERVICE + file-store mutations.
Credential import needed scope, collision, overwrite, and project matching rules. High Phase 4 now requires sanitized IDs, collision rejection, explicit replace=true, and project_id matching.
Redaction proof was narrower than the security requirement. High Validation now covers private_key, private_key_id, raw blobs, generic errors, and request logs.
Compatibility proof did not cover all Phase 0-4 gateway contracts. High Phase 6 now carries an explicit compatibility matrix for OpenAI, Gemini, Vertex, images, and admin security.
The current app-wide auth and CORS flow would let admin routes inherit public gateway behavior. Blocker Phase 4 now requires early /admin dispatch before public route classification/auth and a separate admin-only CORS/auth path.
The two-file config decision had no discovery contract in the current single-GATEWAY_CONFIG_FILE loader. Blocker Phase 1 now defines explicit overlay discovery with GATEWAY_POOL_CONFIG_FILE.
Detailed per-target health on public /readyz would widen unauthenticated metadata exposure. High Phase 3 and Phase 6 now keep /readyz summary-only and move detailed target health to authenticated admin APIs.

Phase Review

Sequential by design. Do not cook dashboard work before runtime pool and mutation/reload contract exist.

Contract and Config Schema

P1 - 0.75-1d

Delivers

  • vertexPools[] with arbitrary length.
  • modelCatalog for Gemini/OpenAI defaults, aliases, allowlists, and disabled models.
  • Admin gates: enableAdminRoutes, adminAllowMutations, adminStoreMode.
  • Docker/VPS adminFileStoreDir config for dashboard import.
  • Startup guard for unsupported Cloud Run + file-store mutations.

Proof Focus

  • Legacy single credential still works.
  • JSON config with 1, 3, or n entries validates.
  • Invalid entries fail fast with actionable errors.
  • Readiness never leaks private key fields.

Credential Pool Runtime

P1 - 1-1.5d

Delivers

  • GenAiRuntime with client, getSnapshot(), and reload().
  • GenAiPoolClient implementing current GenAiClient.
  • Weighted round-robin with disabled target skipping.
  • Atomic validate-build-swap behavior for future admin mutations.

Proof Focus

  • n=1, n=3, and weighted target selection.
  • Successful reload changes future traffic.
  • Failed reload preserves old traffic.
  • Image generation uses the same pool seam.

Health Metrics and Failover

P1 - 1d

Delivers

  • Per-target success/failure counters.
  • Cooldown and target skipping on classified upstream failures.
  • Route-family health labels for Gemini, Vertex, OpenAI Chat, Responses, and images.
  • Pool-aware redacted /readyz.

Proof Focus

  • One failing target cools down and traffic moves on.
  • Invalid client requests do not trigger cross-project retries.
  • Failover before downstream yield, including first upstream iterator.next() rejection.
  • No target switch after the pool wrapper yields the first downstream chunk.
  • Logs include target ID but no prompts or credential data.

Admin API and Persistence

P2 - 0.75-1d

Delivers

  • Opt-in admin auth and API under /admin/api/*.
  • Authorization: Bearer <GATEWAY_ADMIN_TOKEN> is the only admin token transport.
  • Credential import/list/detail/patch/delete/test.
  • Model endpoints backed by modelCatalog.
  • Mutation adapters: static-config and file-store.
  • Mutation rollback if runtime reload fails.

Proof Focus

  • Admin disabled by default and separately authenticated.
  • Gateway API keys, query tokens, and cookies do not authorize admin.
  • OAuth installed/web JSON rejected.
  • Collision requires explicit replace=true.
  • Path traversal and unsafe filenames are rejected.
  • Cloud Run file-store mutation startup guard tested with K_SERVICE.
  • No secret fields in API responses or errors.

Admin Dashboard UI

P2 - 1-1.5d

Delivers

  • Gateway-served static dashboard at /admin.
  • CLIProxyAPI-style JSON import, account cards, detail/edit modal, test, enable/disable, and delete actions.
  • Credentials view with health, actions, and detail/edit drawer.
  • Models view for Gemini/OpenAI provider catalogs.
  • Security/access view with store mode, mutation status, and reload status.

Proof Focus

  • UI cannot submit edits when API reports read-only or guarded mode.
  • Upload clears raw JSON from UI state after request.
  • First screen, modal, and model list render without overlap.
  • No raw service-account JSON in browser storage.
